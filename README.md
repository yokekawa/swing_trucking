# bat_swing_analyzer

動画からバットの芯（先端）が通った軌跡を検出し、1 枚の PNG に重ね描きで
可視化する CLI ツール。

- **v4 (推奨・暗所/ブラーに強い)**: ユーザーがスイング区間内の数フレームで
  バット先端をクリック。スプライン補間で滑らかな軌跡を生成し、背景は
  クリックしたフレームを半透明で重ね合わせた合成画像。追従できているかが
  目視で確認できる
- **v3**: スイング区間 + バット先端の矩形を指定し、CSRT トラッカーで自動追跡。
  明るく高フレームレートの動画向け
- **v2**: 完全自動。画像処理 (MediaPipe Pose + 動体検出 + 輪郭抽出) で
  バットを直接検出。背景がシンプルな動画向け
- v1 (手首からの推定) は未実装

共通方針:
- バットにマーカーやシールは貼らない
- 3D 復元はしない。2D 軌道のみ
- 検出/追跡の信頼度を「線の太さ・透明度」にマッピングして表現

## セットアップ

```bash
python -m venv .venv
source .venv/bin/activate     # Windows Git Bash: source .venv/Scripts/activate
pip install -r requirements.txt
```

Python 3.10〜3.12 を推奨（mediapipe 0.10.14 のホイールがある範囲）。

## 使い方 (v4 推奨)

```bash
python src/analyze_swing_v4.py INPUT.mp4 -o output/trajectory.png
```

1. **スイング区間の選択** — スライダーをドラッグ、`s`=開始、`e`=終了、`Enter`=確定
2. **キーフレーム注釈** — スイング区間内のスライダー上で、
   - **左クリック**: 現在フレームにキーフレームを追加/更新（バット先端位置）
   - **右クリック** または `d`: 現在フレームのキーフレームを削除
   - `Enter` で確定（2 点以上必要）
3. 出力 PNG: クリックしたフレームを半透明で重ねた背景 + 3 次スプライン軌跡 +
   クリック点 (番号付きの白丸)

目安: 5〜10 点程度、スイング中の特徴的な瞬間 (構え、トップ、インパクト、フォロー) に
打っていくと十分滑らかな軌跡になります。

CLI 引数で指定する場合:

```bash
python src/analyze_swing_v4.py INPUT.mp4 -o output/trajectory.png \
    --start-sec 1.2 --end-sec 2.4 \
    --keyframes "180,500,300; 190,520,280; 200,560,240; 210,640,260; 220,720,320"
```

背景合成モード切替:
- `--composite mean` (既定, 半透明アルファ合成)
- `--composite max` (lighten 合成, 明るい被写体を強調)

## 使い方 (v3)

```bash
python src/analyze_swing_v3.py INPUT.mp4 -o output/trajectory.png
```

実行すると 2 つの GUI ウィンドウが順に開きます。

1. **スイング区間の選択**
   - スライダーをドラッグして動画を移動
   - スイング開始フレームで `s` キー
   - スイング終了フレームで `e` キー
   - `Enter` で確定 / `q` で中止
2. **追跡対象の矩形指定**
   - 開始フレームが表示されるので、バットの先端部分を **ドラッグで囲む**
   - `Enter` または `Space` で確定 / `c` でキャンセル
   - 矩形は小さすぎると識別情報が足りず、大きすぎると背景を巻き込みます。
     バット先端 + 周囲 1〜2 バット幅くらいが目安
3. `--preview` を付けると追跡中の矩形がライブ表示され、追跡が外れて
   いないか確認できます

GUI を使わず CLI 引数だけで実行する場合:

```bash
python src/analyze_swing_v3.py INPUT.mp4 -o output/trajectory.png \
    --start-sec 1.2 --end-sec 2.4 \
    --seed-x 620 --seed-y 300 --seed-w 40 --seed-h 40
```

## 使い方 (v2: 完全自動)

```bash
python src/analyze_swing_v2.py INPUT.mp4 -o output/trajectory.png
```

- `INPUT.mp4`: 横からバッター全身が写ったスイング動画
- `-o, --output`: 出力 PNG のパス（デフォルト `output/trajectory.png`）

実行後、コンソールに検出率が表示されます。`raw_detections` が総フレームの
6〜7 割を超えれば実用ラインの目安です。

## パイプライン (v4)

1. ユーザーが GUI で **スイング区間** (start, end フレーム) を指定
2. ユーザーが GUI で **キーフレーム** (frame, x, y) を複数打つ
3. クリック点を `frame_idx` 順にソートし、`x(t)`, `y(t)` を **3 次スプライン** で補間
   (`scipy.interpolate.CubicSpline`, `bc_type='natural'`)。点数 < 3 なら線形
4. クリックしたフレームの画像を読み込み、**半透明 (mean) 合成** または
   **lighten (max) 合成** で 1 枚の背景画像を作成
5. 合成背景の上にスプライン軌跡 + クリック点マーカーを描画して PNG 出力

## パイプライン (v3)

1. ユーザーが GUI で **スイング区間** (start, end フレーム) を指定
2. ユーザーが GUI で **追跡対象の矩形** (バット先端) をドラッグ
3. OpenCV **CSRT トラッカー** (Channel and Spatial Reliability) を矩形で初期化し、
   各フレームの追跡結果から矩形中心を軌跡点として記録
4. トラッカーの成功/失敗、および直近の移動量に対する突発ジャンプ
   (中央値の `MAX_JUMP_FACTOR=4` 倍超) を検出し、怪しいフレームは信頼度 0 に落とす
5. 移動平均 (`SMOOTH_WINDOW=3`) で軌跡をスムージング
6. 信頼度 → 線の太さと α にマッピングして PNG に描画

## パイプライン (v2)

1. **MediaPipe Pose** で各フレームの両手首を取得（バット根本の空間制約）
2. **MOG2 背景差分** と **フレーム差分**（しきい値 + 膨張）を AND して
   動体マスクを作る
3. 動体マスクから **輪郭抽出**。`cv2.minAreaRect` のアスペクト比が
   `ASPECT_MIN` 以上のものをバット候補とする
4. 候補の長軸線が **両手首の中点から `WRIST_GATE_PX` 以内** を通るものを採用
5. 候補の端点のうち **手首から遠い方をバットの芯**（先端）とみなす
6. 欠損フレームは **ギャップ ≤ `INTERP_MAX_GAP` なら線形補間**。それを超える
   ギャップは欠損のままにする
7. 移動平均 (`SMOOTH_WINDOW`) で軌跡をスムージング
8. 信頼度に応じて **線の太さと透明度** を変えて描画

## パラメータ調整

`src/analyze_swing_v2.py` の冒頭定数を編集します。

| パラメータ | 既定値 | 役割 | 上げる／下げる効果 |
| --- | --- | --- | --- |
| `ASPECT_MIN` | 3.0 | バット候補とする最小アスペクト比 | 上げると誤検出減・検出数減、下げると逆 |
| `MIN_CONTOUR_AREA` | 80 | ノイズ除去用の最小面積 (px²) | 上げると小さな誤検出を減らせるが遠景のバット撮影で不利 |
| `MOG_HISTORY` | 300 | MOG2 の学習フレーム数 | 上げると背景モデルが安定、動きの遅い被写体に強い |
| `MOG_VAR_THRESHOLD` | 32.0 | MOG2 の感度 | 下げると動体検出が敏感になるがノイズも増える |
| `DIFF_THRESHOLD` | 25 | フレーム差分の 2 値化しきい値 | 下げると微小な動きも拾う、上げるとバットも消えがち |
| `MORPH_KERNEL` | 5 | モルフォロジーのカーネルサイズ | 大きくすると断裂したバット領域が連結しやすい |
| `MORPH_ITERATIONS` | 2 | 膨張回数 | 大きくするとバット領域が太る（繋がるが周囲と融合する） |
| `WRIST_GATE_PX` | 45 | 手首中点と候補線との最大距離 (px) | 上げると検出寛容、下げると誤検出抑制 |
| `INTERP_MAX_GAP` | 10 | 線形補間する最大連続欠損フレーム数 | 上げると欠損が埋まるが嘘の軌跡が増えるリスク |
| `SMOOTH_WINDOW` | 5 | 移動平均のウィンドウ (frames) | 上げると軌跡が滑らかになるが遅延・丸めが強くなる |
| `MIN_CONF` | 0.15 | 描画に用いる最小信頼度 | 上げると確信度の低い軌跡を非表示にできる |

### 典型的なチューニング

- 検出率が低い: `WRIST_GATE_PX` を大きく、`ASPECT_MIN` を 2.5 へ下げる
- 人物の周囲が誤検出される: `MIN_CONTOUR_AREA` を 150〜250 に上げる、
  `ASPECT_MIN` を 3.5〜4.0 に上げる
- 軌道がガタつく: `SMOOTH_WINDOW` を 7〜9 へ上げる
- 欠損が多く軌跡が途切れる: `INTERP_MAX_GAP` を 15 に上げる（ただし長い
  欠損区間を埋めすぎると誤認識が強調される）

## 既知の課題 / 未対応

- カメラ手ブレ補正（固定カメラ前提）
- スイング区間の自動検出（現状は動画全体を処理）
- モーションブラー対策
- 背景に動くものが多い場合の ROI 絞り込み
- HEVC など特定コーデックが OpenCV で開けないケース

v2 の精度が伸び悩む場合は、YOLOv8 等を用いたバット検出モデルのファイン
チューニングに切り替える想定です（Roboflow Universe の baseball bat
データセット利用を検討）。

## 撮影ガイド

- 横から全身が入る構図
- 60fps 以上推奨
- 固定カメラ（三脚）
- 手元・バットが明るく写っていること
