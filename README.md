# bat_swing_analyzer

動画からバットの芯（先端）が通った軌跡を検出し、1 枚の PNG に重ね描きで
可視化する CLI ツール。MVP として、画像処理ベースでバットを直接検出する
v2 パイプラインのみを実装しています（v1: 手首からの推定は未実装）。

- バットにマーカーやシールは貼らない。画像から直接検出する。
- 3D 復元はしない。2D 軌道のみ。
- 検出の信頼度を「線の太さ・透明度」にマッピングして、悪条件でも
  「太く曖昧に」軌跡を出す方針。

## セットアップ

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Python 3.10 以降を推奨。

## 使い方

```bash
python src/analyze_swing_v2.py INPUT.mp4 -o output/trajectory.png
```

- `INPUT.mp4`: 横からバッター全身が写ったスイング動画
- `-o, --output`: 出力 PNG のパス（デフォルト `output/trajectory.png`）

実行後、コンソールに検出率が表示されます。`raw_detections` が総フレームの
6〜7 割を超えれば実用ラインの目安です。

## パイプライン (v2)

1. **MediaPipe Pose** で各フレームの両手首を取得（バット根本の空間制約）
2. **MOG2 背景差分** と **フレーム差分**（しきい値 + 膨張）を AND して
   動体マスクを作る
3. 動体マスクから **輪郭抽出**。`cv2.minAreaRect` のアスペクト比が
   `ASPECT_MIN` 以上のものをバット候補とする
4. 候補の長軸線が **両手首の中点から `WRIST_GATE_PX` 以内** を通るものを採用
5. 候補の端点のうち **手首から遠い方をバットの芯**（先端）とみなす
6. 欠損フレームは **ギャップ ≤ `INTERP_MAX_GAP` なら線形補間**。それを超える
   ギャップは欠損のままにする
7. 移動平均 (`SMOOTH_WINDOW`) で軌跡をスムージング
8. 信頼度に応じて **線の太さと透明度** を変えて描画

## パラメータ調整

`src/analyze_swing_v2.py` の冒頭定数を編集します。

| パラメータ | 既定値 | 役割 | 上げる／下げる効果 |
| --- | --- | --- | --- |
| `ASPECT_MIN` | 3.0 | バット候補とする最小アスペクト比 | 上げると誤検出減・検出数減、下げると逆 |
| `MIN_CONTOUR_AREA` | 80 | ノイズ除去用の最小面積 (px²) | 上げると小さな誤検出を減らせるが遠景のバット撮影で不利 |
| `MOG_HISTORY` | 300 | MOG2 の学習フレーム数 | 上げると背景モデルが安定、動きの遅い被写体に強い |
| `MOG_VAR_THRESHOLD` | 32.0 | MOG2 の感度 | 下げると動体検出が敏感になるがノイズも増える |
| `DIFF_THRESHOLD` | 25 | フレーム差分の 2 値化しきい値 | 下げると微小な動きも拾う、上げるとバットも消えがち |
| `MORPH_KERNEL` | 5 | モルフォロジーのカーネルサイズ | 大きくすると断裂したバット領域が連結しやすい |
| `MORPH_ITERATIONS` | 2 | 膨張回数 | 大きくするとバット領域が太る（繋がるが周囲と融合する） |
| `WRIST_GATE_PX` | 45 | 手首中点と候補線との最大距離 (px) | 上げると検出寛容、下げると誤検出抑制 |
| `INTERP_MAX_GAP` | 10 | 線形補間する最大連続欠損フレーム数 | 上げると欠損が埋まるが嘘の軌跡が増えるリスク |
| `SMOOTH_WINDOW` | 5 | 移動平均のウィンドウ (frames) | 上げると軌跡が滑らかになるが遅延・丸めが強くなる |
| `MIN_CONF` | 0.15 | 描画に用いる最小信頼度 | 上げると確信度の低い軌跡を非表示にできる |

### 典型的なチューニング

- 検出率が低い: `WRIST_GATE_PX` を大きく、`ASPECT_MIN` を 2.5 へ下げる
- 人物の周囲が誤検出される: `MIN_CONTOUR_AREA` を 150〜250 に上げる、
  `ASPECT_MIN` を 3.5〜4.0 に上げる
- 軌道がガタつく: `SMOOTH_WINDOW` を 7〜9 へ上げる
- 欠損が多く軌跡が途切れる: `INTERP_MAX_GAP` を 15 に上げる（ただし長い
  欠損区間を埋めすぎると誤認識が強調される）

## 既知の課題 / 未対応

- カメラ手ブレ補正（固定カメラ前提）
- スイング区間の自動検出（現状は動画全体を処理）
- モーションブラー対策
- 背景に動くものが多い場合の ROI 絞り込み
- HEVC など特定コーデックが OpenCV で開けないケース

v2 の精度が伸び悩む場合は、YOLOv8 等を用いたバット検出モデルのファイン
チューニングに切り替える想定です（Roboflow Universe の baseball bat
データセット利用を検討）。

## 撮影ガイド

- 横から全身が入る構図
- 60fps 以上推奨
- 固定カメラ（三脚）
- 手元・バットが明るく写っていること
